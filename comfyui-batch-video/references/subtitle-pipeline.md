## 一点五、分辨率与放大策略（重要）

**两级规格，别混用**：

| 阶段 | 分辨率 | 帧率 | 时长 |
|---|---|---|---|
| ComfyUI 生成原始片 | 736×1312（9:16） | 24fps | 5.17s / 124 帧 |
| 可发布成品 | **1080×1920** | 30fps | 约 5.17s，AAC 44.1kHz |

放大链路（两条管线一致）：

```
scale=1080:1920:force_original_aspect_ratio=increase, crop=1080:1920, setsar=1
```

736×1312 的比例是 0.5610，目标 0.5625，几乎同比例——所以**实际是纯放大 1.47 倍，
裁切只有约 2~3 像素**，不会吃掉画面。

### 放大效果到底有多大

实测同一帧（蝙蝠科普，取 400×400 细节区），拉普拉斯方差（越大越锐）：

| 方案 | 锐度 | 评价 |
|---|---|---|
| 源片 736 宽 | 153.3 | 基准（尺寸不同，仅参考） |
| bicubic 放大 | 77.4 | ffmpeg 默认，最软 |
| lanczos 放大 | 83.7 | +8%，免费无副作用 |
| lanczos + unsharp 0.9 | 185.5 | 边缘利落，但已偏强 |

结论：**lanczos + unsharp 0.4~0.6 是性价比最高的默认档**——视觉上明显更利落，
不产生白边光晕；0.9 以上开始有"脆"感，不适合大面积皮肤/天空。

### 有没有更好的方案

| 方案 | 效果 | 代价 | 建议 |
|---|---|---|---|
| 提高生成分辨率（直接出 1080×1920） | 真正增加信息量 | 像素量 2.16 倍，显存与耗时显著上升；且 736×1312 接近模型原生尺寸，跳太多可能反而出畸形 | 需单条实测再决定，不要全量切 |
| AI 超分（Real-ESRGAN 等） | 真实细节合成，卡通类提升明显 | 124 帧/条，约 1~3 s/帧 → 单条多花 2~6 分钟；有引入伪影风险 | 只对重点片做，不做全量 |
| 保持 736×1312 不放大 | 无损 | 不符合平台 1080×1920 规格 | 平台接受时才用 |
| lanczos + 轻锐化 | 视觉提升明显 | 几乎为零 | **默认方案** |

一句话：**放大不能凭空造出细节**。1080×1920 是"合规"，不是"更清晰"；
要真提质，只能回到生成端或上 AI 超分。

## 二、轻量路线（本技能脚本）

```bash
# 已有 cues：直接烧
python scripts/add_subtitles.py --video in.mp4 --cues cues.json --head "5秒涨知识"

# 有 faster-whisper 结果：自动切行 + 重点词高亮
python scripts/add_subtitles.py --video in.mp4 --asr asr.json \
    --key 三个心脏 --key 触手 --head "5秒涨知识" --tail "关注我"

# 只出 ASS 不烧录（交给剪映或其他工具）
python scripts/add_subtitles.py --video in.mp4 --asr asr.json --ass-only --ass-out sub.ass
```

样式沿用已验证的《5秒钟涨知识》规范：微软雅黑、普通句 78px 米白、重点词 96px 金黄带弹跳、
距底 420px 安全区、1080×1920 画布。

## 三、完整包装路线（工作区 tools/）

顺序固定，别跳步：

```bash

.venv\Scripts\python.exe tools\asr_transcribe.py

# 2) 清洗 ASR：繁转简 + 同音错字 + 无配音幻觉识别

.venv\Scripts\python.exe tools\make_draft.py "data/plans/001_章鱼三个心脏.json"

# 批量（自动建计划+渲染+建草稿）
.venv\Scripts\python.exe tools\batch_build.py --start "Pika_H3_Flex_T2V_00021_.mp4"
```

产出：`output/成品/<分类>/5秒涨知识_<编号>_<标题>.mp4` + 同名剪映草稿；清单 `output/成品/视频清单.md`。

## 四、ASR 环境（GPU）

- 模型：`data/models/faster-whisper-medium`（`model.bin` 必须完整，1.5GB；残缺会表现为"一直卡住"）
- CUDA 依赖：`.venv/Lib/site-packages/nvidia/{cublas,cudnn}/bin`，脚本需自动 `os.add_dll_directory()` 注册
- 速度：GPU 加载约 4s、单条约 1.4s；CPU 约 60s，差 40 倍
- 识别库版本与 CUDA 大版本要匹配（CUDA 12 需对应 cublas/cudnn 12）

## 五、ASR 质量清洗规则（必做）

faster-whisper 在**没有语音**的片段会输出幻觉文本，必须过滤，否则会做出莫名其妙的字幕：

| 类型 | 表现 | 处置 |
|---|---|---|
| 幻觉 | `字幕由 Amara.org 提供`、`优优独播剧场`、`MING PAO`、`by bwd6` 等 | 清空，标记 `no_speech` |
| 过短 | 文本长度 < 4 字 | 视为无有效语音 |
| 繁体 | `太陽光跑到地球` | `opencc t2s` 转简体 |
| 同音错字 | `赖水`→`泪水`、`牙菌般`→`牙菌斑`、`酌木鸟`→`啄木鸟` | 维护替换表，逐条修 |

判定"无配音"的片子：成品照出，但**不加字幕**，单独列入清单等补配音，不要硬凑字幕。

## 六、这一段的坑（都踩过）

1. **`trange(开始, 时长)` 不是 `(开始, 结束)`**：pyJianYingDraft 的时间范围参数是"起点+时长"，
   当成"起点+终点"会让每条字幕都超长。
2. **同一轨道不允许时间重叠**：一行里的"重点词"和"普通字"是两个片段，必须各自独立轨道；
   贴纸同理，每个贴纸一条视频轨道。
3. **成品尾部多出 0.2~0.4 秒定格**：贴纸序列比正片长，拖长了输出。用 `-t <原片时长>` 精确截断。
4. **音频采样率不统一**：混音后统一 44.1kHz / AAC 192k，否则剪映里会不同步。
5. **同名覆盖**：不同来源的视频若都从 `00001` 起编号，会互相覆盖。命名必须带系列前缀
   （`T2V_` / `REF2V_` / `ContentForge_`），计划文件名也要带。
6. **片尾文字挤不下**：字幕说到片尾时要让位；剩余不足约 0.55 秒就按原则省略片尾，不要硬塞。

## 七、验收

- `ffprobe` 查时长、分辨率、音轨
- 抽帧看字幕是否在安全区内、有没有被贴纸压住
- 重点词是否变色放大、栏目名是否就位
- 剪映里实际打开草稿播放一遍，别只看文件是否生成
